This audio overview explains the Administrator tab of the D B bun Invisible Illness Burden Simulator. It was developed by Dr. Uri Kartoun, founder of D B bun L L C, in Cambridge, Massachusetts. The Administrator tab exists only in the full tool, which runs on Dr. Kartoun's computer. The public demonstration hides it, because it changes the federal evidence library and can start paid model runs. The real screens are shown on the Frequently Asked Questions page, and this recording describes what they do and why they matter.

Why does an administrator page matter in a tool for patients, care teams and policy analysts? Because every simulator is only as good as the evidence it is checked against. The Administrator tab is where that evidence is managed, and where the tool can grow, in principle, beyond Lyme disease and Long COVID. For an analyst or a federal data team, it is the part that answers the question: what exactly is in the library, where did it come from, and how was it processed?

The first control is the choice of artificial intelligence model. Claude is the default. An administrator can choose another configured model for the next simulation, and an OpenAI model is supported as well. Simulators already made keep the model recorded in them, and the library shows that model on each row. Keys are never typed into the page; each stays in a private file on the server. Whichever model is chosen, it writes only the wording and the specification. Code does every calculation and every federal check.

Below that is a summary of the federal knowledge library, with counts of raw files and review units, and a table of the federal agencies behind the evidence. Agencies are ranked by how many of their review units are specifically about Lyme disease or Long COVID, not just general background, so the most relevant agencies come first. Expand an agency to see each dataset, its files, the extractor that reads it, its condition scope, and its relevance.

Three terms matter here. A raw file is a file exactly as downloaded from the federal agency, such as a spreadsheet, a P D F or a zip archive. A dataset is one named federal data program, for example Centers for Disease Control and Prevention Lyme disease surveillance, usually made of several raw files. A review unit is one processed, evidence-ready package built from a raw file, or from one part of it, such as one tab of a spreadsheet. It is a short text summary with the facts and caveats extracted from that file. Review units are what the retrieval step searches, and what the artificial intelligence model is shown excerpts of. The model never reads the raw federal files.

Every review unit is tagged with a condition scope, based on its own content: Lyme and Long COVID, Lyme only, Long COVID only, general background, or not yet classified. General background means useful context, such as wages or provider counts, that is not specific to either condition.

Next is Browse the evidence. Everything the simulators draw on can be opened here. Choose a resource to list its review units, then open any one to read exactly what the model could be shown. Evidence cards are different: they are numbers the system computes itself, such as survey-weighted counts, national Lyme case totals and the inflation index. Each card shows its method and its limits, and can be downloaded with its full data table.

Then comes the part that changes the library: Re-process selected. Select one or more datasets and click the button. The current review units are first backed up to a timestamped folder, so nothing is deleted until a safe copy exists. They are removed from the live index. The raw files are re-read from disk and turned back into review units using that dataset's extractor, and every unit is re-tagged with its condition scope. If any step fails, the backup is restored automatically, so the live library is never left half-updated. This is deterministic parsing. No artificial intelligence model is called during re-processing.

An extractor is a piece of this project's own Python code that knows how to read one particular raw file format, such as a multi-tab workbook, a fixed-width survey file or a zip of C S V files. Every extractor was written for this project by Claude, working under the direction of Dr. Kartoun. There is no separate vendor.

Next is Add new resource. It registers a dataset's name, agency and a note. It does not download anything: the raw files must already exist in the right folder on the computer, or the form rejects the resource. A newly added resource starts with zero review units until you select it and click Re-process. Until a dedicated extractor is written, it uses a generic fallback reader. This is the scaling path. In principle, a team that wants to extend the tool to another condition would register that condition's federal resources here. It has been done only for Lyme disease and Long COVID. For other conditions, no curated federal evidence exists yet.

The page also explains where machine learning actually happens. Not on the Administrator page. Everything here is deterministic file parsing. Machine learning runs later, on the generate page, when a document is uploaded: a classifier decides whether it is about Lyme disease, Long COVID or neither, and then a retrieval model scores every review unit in the library for relevance to that document and selects the ones the artificial intelligence model is shown. It always searches whatever is currently in the library, so re-processing here is what determines what later runs can find.

How was the list of resources chosen? Most of the library was acquired and formally reviewed over a few days in August twenty twenty-six, and each source was accepted for a specific, named modeling role. For example, regional economic data supply lost-income denominators, and a health-workforce source supplies provider access and diagnostic-delay context. That acquisition was then locked. New sources are added only when one of five specific triggers is true: the simulator cannot compute a required output, a field cannot be safely interpreted, provenance is wrong, validation shows a real coverage or bias problem, or sprint feedback explicitly requires it. Every item on the organizers' own resource list was checked against the library. One case shows the discipline. A bulk consumer-expenditure microdata file was attempted, but the statistics agency denied automated retrieval, and that limitation is kept on record. A different product from the same agency, its published income-bracket tables, was acquired instead.

Finally, are all registered datasets actually used? No. A review unit is shown to the model only if it is tagged as specific to Lyme disease or Long COVID, or its dataset is on a short list of general-purpose sources explicitly allowed in, or, for regional economic data only, a document names a matching state. Other general datasets are fully processed and stored but never shown to the model, and the table marks those rows. The page says openly that whether such data should be retrievable is a narrower, later question that was not evaluated for most datasets.

So the Administrator tab shows the opposite of a black box. It lets someone see what is in the evidence library, why it is there, how it was processed, how it is searched, and what it can and cannot do. That openness is part of the potential for reuse: the same structure, in principle, could hold evidence for other conditions. It has not been tested beyond the two conditions the tool was built for.

Once more: this is an educational what-if tool, not medical advice. Thank you for listening.
